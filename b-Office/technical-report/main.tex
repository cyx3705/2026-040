\begin{abstract}
Echo is a local prototype for English conversation and assisted reading by Chinese-speaking learners. It couples human selection of predicted words with dictionary-bounded, context-sensitive Chinese glosses. One native runtime, one quantized 8B model, and one fixed KV pool serve three uses of the same constrained-label mechanism: transient sense-selection branches forked from a streaming response's computed prefix, batched selection branches from a prefilled webpage passage, and selection of an English dictionary candidate for a Chinese word typed during composition. The model never generates the gloss itself: it chooses among dictionary entries or abstains, and the dictionary supplies the text. Learned lemmas bypass lookup and selection, and recognized failures use an explicitly marked dictionary default. We describe the interaction, cache ownership, prompts, and bounded scheduling, and consolidate existing engineering observations on one laptop GPU. Four curated passages yield 16 correct target decisions across two scheduling modes, representing eight unique occurrences; this is a smoke test, not a semantic benchmark. Recorded incremental prediction medians range from 9.5 to 26.2\,ms after the first request, excluding frontend delay. The report documents a working integration and its limits; it does not establish educational benefit, general semantic accuracy, or a new cache-sharing algorithm.
\end{abstract}

\section{Motivation and contribution}
Producing a full English sentence can be difficult even when a learner recognizes many of its words. Echo lets a learner compose an utterance by alternating ordinary typing with deliberate acceptance of model suggestions. During reading, Chinese glosses support unfamiliar words and disappear when the learner marks their lemma as known. The intended unit of interaction is a word occurrence, although the model operates on subword tokens.

The technical question is how to offer this assistance on one consumer GPU without loading a second model or generating a separate free-form translation for every word. Echo reuses one model's computed context, introduces short selection tasks only when dictionary ambiguity requires them, and releases each transient branch immediately after selection. Existing webpage text is prefilled as input rather than regenerated as an artificial assistant response.

This is an implementation report. Predictive text navigation, collaborative writing, constrained decoding, word-sense disambiguation, and prefix reuse all have established predecessors (Section~\ref{sec:related}). What we document is their combination in one learner-facing system:
\begin{itemize}\setlength{\itemsep}{1pt}
\item \textbf{Causal branching from live generation.} A sense-selection branch references the \emph{actually computed} KV prefix of a still-streaming response at the target word, never later text, and is released as soon as one label is chosen (Section~\ref{sec:architecture}).
\item \textbf{Prefilled-passage batching.} For reading, an existing passage is prefilled once as input; two occurrence-specific branches share it and are decided in one native batch (Section~\ref{sec:architecture}).
\item \textbf{Dictionary-bounded finite choice.} All three uses reduce to choosing a label among dictionary entries plus an abstention label, with deterministic, visibly marked fallback (Section~\ref{sec:selection}).
\item \textbf{An engineering record with stated limits.} Latency, lifecycle, and isolation observations are reported with their date, hardware, repetitions, and confounds (Section~\ref{sec:results}).
\end{itemize}

\section{Interaction model}
\label{sec:interaction}
The composer filters and deduplicates one top-20 next-token ranking through the dictionary, displaying five suggestions by default (configurable up to 20). Accepting a candidate extends user text and triggers a new ranking. Shift+Space or Tab accepts; ordinary Space inserts a space. Users can also type and edit freely. A partial word is not fed to the model; the ranking is taken before the word and filtered by the typed prefix, with dictionary-frequency completion when model candidates are insufficient. The interface exposes local alternatives rather than a full continuation tree. Dictionary membership does not prove a token ends a word: multi-token words may be missed and fragments accepted.

While Ctrl is held, a native child control hosts the system Chinese input method inside the composer. An ordinary Space after the committed Chinese confirms it as one word, which Echo replaces by a selected English dictionary candidate (Section~\ref{sec:reverse}).

\section{Runtime architecture and cache ownership}
\label{sec:architecture}
Echo 0.3.0 uses a local FastAPI service and browser UI. Python owns HTTP/SSE transport, prompts, dictionary access, learned-state persistence, and orchestration. C++ owns model execution: tokenization, KV state, batching, sampling, next-token ranking, constrained decoding, and branch cleanup. SQLite already performs database operations in native code. Ollama supplies model management and bundled llama.cpp libraries; Echo's adapter loads the GGUF and library directly because the ordinary generation HTTP interface does not expose the needed live sequence handles. Third-party binaries are not patched.

\subsection{Generated text: historical-prefix branching}
Chat source A streams English. After a complete word is recognized, the selector checks learned status, then dictionary coverage and ambiguity. A multi-sense occurrence receives a stable identity and a target position. B references the actual computed A prefix through that word using \code{llama\_memory\_seq\_cp}. Merely sampled text is not assumed to have KV. If the word ends inside a token, B starts at the preceding valid token boundary and recomputes only the necessary text remainder. It does not inherit a later word, even if A has already advanced. B closes the inherited assistant turn with the model's own template tokens, appends an internal user task, and opens a new assistant turn; A's turn and history are untouched.

At most one chat B is live. With scheduling mode 2, its task prefill yields after 64-token chunks so A can continue; mode 1 defers selection until A finishes. These are scheduling policies on one GPU. Native locking preserves A's pending sample and logits against B's evaluation. B results are streamed by occurrence and retained with conversation history. Pending work is bounded to eight descriptions, not eight KV snapshots; overflow falls back. A remains alive for bounded cleanup, with a 30-second tail deadline.

\subsection{Supplied text: shared input prefix}
For reading, P contains the full quoted passage and a fixed acknowledgement, followed by an open task turn. Native \code{select\_batch} accepts this unsampled input source and rejects a generating chat source. Sequence slots 1 and 2 reference P's slot 0 prefix, then hold distinct suffixes and final logits rows. Both branches are removed before return; the source is released in a \code{finally} path. Cancellation during remote prefill retains and releases any late sequence handle. This ownership rule prevents a cancelled caller from simply losing track of a live source.

\section{Finite-choice selection}
\label{sec:selection}
Let $P$ denote an already computed prefix and $S_i$ the task suffix for occurrence $i$. Its dictionary senses are $D_i=\{d_{i1},\ldots,d_{im}\}$. For the reader, assign each sense a unique single-token label and include an abstention label $0$. The runtime chooses
\begin{equation}
 \hat{\ell}_i = \arg\max_{\ell\in\mathcal L_i}
 z_\theta\!\left(\ell\mid P,S_i\right),\qquad
 g_i = \begin{cases}D_i[\hat{\ell}_i],&\hat{\ell}_i\ne0,\\
 d_i^{\mathrm{default}},&\hat{\ell}_i=0.
 \end{cases}
\end{equation}
Here $z_\theta$ is the next-token logit and the dictionary mapping, not generated Chinese text, supplies $g_i$. Only allowed labels compete. These logits are not calibrated probabilities of correctness.

The reader supports up to 52 sense labels (A--Z, a--z), plus abstention. Letter labels have a leading space and must tokenize to unique individual tokens for the active model. Each occurrence therefore needs one output decision even when its Chinese gloss contains several tokens. This is not a claim of one GPU invocation for the whole request: shared-prefix prefill and occurrence-specific suffix prefill still cost time, and suffixes are evaluated in chunks. Missing suitable dictionary senses cannot be repaired by the constrained selector.

\subsection{Task injection and context boundaries}
The reader system instruction asks for the Chinese dictionary sense, permits the full passage including later text, treats passage and choices as quoted data, and requests abstention when no sense fits or the meaning is uncertain. A task suffix identifies the repeated occurrence using its offset, marks the local sentence, lists every sense with part of speech, closes the user turn, and opens an assistant turn at \code{Label:}. A shortened illustration is:

\begin{quote}\small
\textbf{Shared input:} He sat on the bank beside the river. She went to the bank to get a loan.\\
\textbf{Branch task:} Translate ``bank'' at the marked occurrence.\\
Sentence: He sat on the \code{<target>}bank\code{</target>} beside the river.\\
Choices: A: \zh{岸} (noun); B: \zh{银行} (noun). Return a letter, or 0 if none fits.\\
\textbf{Allowed output:} \code{\{0,\ " A",\ " B"\}}. Map the chosen label to its dictionary string.
\end{quote}
The illustration reduces the real candidate inventory for readability. Chat B instead explicitly receives only preceding conversation and the target, prohibits assuming unseen continuation, and distinguishes absent phrase senses from synonymous valid senses. It uses the Chinese candidate strings themselves as constrained outputs in a token trie and stops at the first token that identifies a unique candidate, within at most 16 decision steps and a 640-token task prompt. During development, letter labels in the chat path mis-selected a sense of \emph{dishes} on the active model, which motivated this choice. Unlike the reader's ASCII-label path, chat selection can therefore require several output decisions.

\subsection{Reverse lookup during composition}
\label{sec:reverse}
When the learner confirms a Chinese word of 1--32 characters, a reverse ECDICT query returns up to 20 English words or phrases, preferring complete senses and then frequency. The prompt contains the conversation history, the composer text on both sides of the word, the Chinese word, and the candidates labelled A--T. Echo prefills this prompt as a temporary source, forks one branch, appends \code{Label:}, and takes a single constrained decision over space-prefixed letter tokens and \code{0} (budget 1); branch and source are then released. Multi-token words and phrases are inserted whole from the dictionary. No dictionary candidate or abstention leaves the Chinese text in place; there is no free-form translation fallback. Five recorded HTTP examples (e.g.\ \zh{苹果}$\to$\emph{apple}, \zh{冰淇淋}$\to$\emph{ice cream}) each used one decision and took about 266--664\,ms including lookup and prefill.

\subsection{Learning state, fallback, and bounded work}
Learned status is stored by lemma and checked before Chinese lookup or inference; marking a word learned also suppresses pending results. One available sense is displayed directly. No entry yields no invented Chinese. Ambiguous occurrences go to the selector. A valid result has no fallback underline; abstention, budget exhaustion, overflow, timeout, or runtime failure uses the deterministic default with an underline (wavy in the reader) and a recorded reason. The mark signals recognized fallback, not a detector of all wrong meanings. A confident wrong sense can remain unmarked.

The native pool is fixed at 4,096 tokens with three sequence slots; source admission reserves 768 tokens for branch work. Reader suffixes are limited to 640 tokens each and 704 in combination, otherwise they run singly or fall back. Prefix sharing avoids repeated prefix storage and prefill, while suffixes still consume additional capacity. Releasing a branch makes pool space reusable and need not reduce preallocated VRAM.

\section{Existing engineering observations}
\label{sec:results}
This section consolidates recorded outputs of the repository's test scripts, mostly from 24 October 2026, rather than reporting a new evaluation. The recorded machine has an RTX 4080 Laptop GPU (12\,GB VRAM), 32\,GB system RAM, and Windows x64. The model is \code{qwen3:8b}; the bundled engine is Ollama 0.40.7 with a llama.cpp b11738 ABI. Exact model-file hashes, complete driver details, and raw per-request traces are not included in the records used here, limiting reproducibility. No human-subject or learning-outcome experiment was performed.

\subsection{Lifecycle, isolation, and verification status}
Native chat acceptance passed 14 curated cases, including abstention, with a median selection latency of 204.4\,ms (suffix tokenization, fork, prefill, and decision; A generation excluded). A 1,000-cycle fork/release check took 23.93\,s and finished with zero active source and branch handles; cumulative fork and release counts both reached 1,016 including other checks. A fixed-seed test (seed 73) preserved A's output with short and long B tasks. These checks support lifecycle accounting and limited sampling isolation; they neither measure physical KV bytes nor prove leak freedom or determinism for all workloads. Longer B tasks can still interrupt A on the shared GPU: in the same run, A's inter-token P50 was about 14\,ms alone and its P95 about 39\,ms with a long B inserted.

An isolated Edge session exercised the actual Manifest V3 extension and local inference path. Fixture-based browser checks separately covered learned-state reversal, UTF-16 offsets, words spanning tags, dynamic text, fallback marking, and DOM restoration. Chrome loading and arbitrary websites have not been validated. The latest recorded application regression had 54 of 55 Python tests passing: 14 C++ inference groups passed, but the Windows \code{input\_tests.exe} process exited with code 3221226505, with its cause unresolved. We therefore do not describe the complete latest suite as passing. The manuscript build adds no new model, browser, or GPU measurements.

\section{Related work}
\label{sec:related}
Dasher uses a language model to allocate space to likely continuations and lets people navigate predictive text through continuous gestures~\cite{dasher}. It precedes human control of model-informed text entry; Echo applies local word suggestions to bilingual assistance. CoAuthor studies human--AI collaborative writing through recorded interaction sessions~\cite{coauthor}. Echo's present evidence is an engineering record rather than an interaction study. GlossBERT uses gloss knowledge for word-sense disambiguation~\cite{glossbert}; contextual sense selection itself is established, whereas Echo focuses on runtime integration and interaction.

Grid Beam Search enforces lexical constraints in sequence generation~\cite{hokamp}, and grammar- or regex-guided decoding restricts outputs to a formal language~\cite{outlines}; Echo restricts a short classification output to dictionary-sense labels. PagedAttention in vLLM shares KV blocks across sequences with copy-on-write~\cite{vllm}, SGLang combines structured language-model programs with prefix reuse through RadixAttention~\cite{sglang}, and Hydragen targets shared-prefix query throughput~\cite{hydragen}. Echo integrates llama.cpp sequence-prefix sharing~\cite{llamacpp} into a learner-facing prototype, without introducing a new attention algorithm or a throughput comparison against those systems. Its distinctive constraint is ownership rather than throughput: branches fork from a source that is still generating, at a past position, on one consumer GPU.

The implemented branches perform local selection and are discarded. They do not expand competing reasoning trajectories, backtrack, or promote a winning continuation. Shared KV could support search, but this system does not implement Tree of Thoughts~\cite{tot}.

\section{Limitations and intended interpretation}
Semantic quality is the main open question. The dictionary may omit a phrase sense, split meanings poorly, or assign unsuitable morphology. Chat branches are deliberately causal: at ``the bank'', later words could determine a meaning that the branch cannot yet know. A reader branch sees later text only inside its supplied chunk. Abstention is useful but uncalibrated, and successful decoding certifies only membership in a finite set, not a correct translation. The reader and composition paths compare a bare \code{0} with space-prefixed letter tokens; project notes identify such tokenization asymmetry as a possible source of label bias, which has not been measured here. The 16 reader decisions are an integration smoke test, not a success-rate estimate for ordinary browsing.

No evidence here establishes vocabulary retention, writing improvement, reduced cognitive load, or superiority to ordinary predictive keyboards and dictionary glosses. Suggestions may bias learners toward frequent expressions. A learned flag records a user's choice, not measured mastery. Fair educational or interaction comparisons require separate studies. Engineering limits include a small fixed KV pool, bounded queues, model-specific templates and ABI assumptions, GPU contention, and a Windows-specific input bridge with an unresolved regression. These constrain the prototype's present deployment scope.

\section{Reproduction and artifact scope}
\label{sec:reproduction}
The report describes Echo 0.3.0 at the working-tree inspection of 24 October 2026. It accompanies the implementation rather than claiming a public release or an immutable benchmark package. The tables transcribe the JSON outputs of the repository's test scripts from the recorded runs; the project conventions document (\code{b-Office/}\zh{现行约定}\code{.md}) summarizes them, partly as rounded ranges. Re-running the scripts produces new observations, not the exact historical traces.

The existing native setup requires Windows x64, Python 3.12 or later, Visual Studio C++ Build Tools and the Windows SDK, the local model, and the ECDICT SQLite dictionary~\cite{ecdict}. The native adapter uses bundled llama.cpp~\cite{llamacpp}. With dependencies prepared and Echo running idle, the following repository-root commands invoke the relevant checks. GPU checks should run serially.
\begin{quote}\footnotesize\ttfamily
uv run -{}-project b-Code-Echo python\\
\hspace*{1em}b-Code-Echo/tests/native\_reader\_acceptance.py\\[3pt]
uv run -{}-project b-Code-Echo python\\
\hspace*{1em}b-Code-Echo/tests/native\_suggest\_performance.py -{}-repeats 5\\[3pt]
uv run -{}-project b-Code-Echo python\\
\hspace*{1em}b-Code-Echo/tests/native\_acceptance.py -{}-cycles 1000
\end{quote}
Each visual line pair above is one command. The reader test temporarily treats its target lemmas as unknown in memory; it does not write learned state or user settings. Other currently learned words are skipped, so local learned-state differences can change total work and timing. Live extension validation additionally uses \code{node b-Code-Echo/tests/reader\_browser.cjs -{}-live}, Playwright, and installed Edge. In the latest recorded shell, \code{uv} was unavailable and application regression used the existing virtual environment instead.

The extension sends extracted passage text to loopback, not page URLs, HTML, cookies, or form contents, and stores no webpage history. It excludes editable/form/code regions and processes visible text in chunks of about 600 UTF-16 units. Normal word clicks toggle learned status; links require Alt+click so normal navigation remains usable. These are implementation boundaries, not a security audit. Quoting text as data reduces instruction confusion but does not prove immunity to adversarial webpage content. Source licensing remains as declared in the repository; no arXiv submission or redistribution license is selected by this manuscript.
