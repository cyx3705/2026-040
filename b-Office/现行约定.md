## 取舍

- **托管在 OneHistory，但不做成宿主模块。** 和机器人、创业类项目一样，Echo 照旧用 OneHistory 的编号、仓库、站点和文档规则，但它是独立应用：不接 Vulcan/Aurora，不注册指令。逐词交互是定制界面，塞进 Aurora 会违反「不加专用组件」的原则。
- **推理走 Ollama，不自建 llama.cpp。** Ollama 的 `/api/generate` 加上 `raw:true`、`logprobs:true`、`top_logprobs:5`，就能直接给出下一 token 的前 5 候选，够用。只有 Ollama 满足不了时才换框架。
- **预测用户输入靠续写 user 回合。** 把对话按模型自己的聊天模板拼好，结尾停在 user 回合里用户已经打出的内容（不闭合回合），用 `raw` 模式让模型接着写，预测出来的就是用户的下一个词。生成 AI 回复则走 `/api/chat`，并设 `think:false` 关掉 qwen3 的思考模式。
- **候选单位是整词，不是 token。** 模型候选里会出现半个词或标点，比如 ` pepp`、`-style`。每个半截候选要继续贪心补全，直到遇到空格或标点，再去重、滤掉纯标点，凑满 5 个整词。
- **默认模型 `qwen3:8b`。** 本机已装、整模在 GPU 上、延迟够低。要更地道的英语时，再和本机已有的 `gemma4:12b` 或 `qwen3:14b`（4bit 约 9GB）对比后再换。
- **词典用 ECDICT 全量 SQLite。** 用 `exchange` 字段把变形词还原成原形再查。一词多义时先按常用度列出全部义项；以后再让 AI 按上下文标出当前用的义项，作为增强功能。
- **界面是本地网页。** 逐词双行排版（英文在上、中文小字在下）和候选按钮，用 HTML 做最省事。

## 真机实测（2026-10-22）

- 机器：RTX 4080 Laptop（12GB），32GB 内存，Ollama 0.40.7。
- `qwen3:8b` 整模在 GPU 上，占 5.6GB。热态加前缀缓存命中时，单次前向约 20ms；缓存未命中时约 200ms。
- 冷启动加载模型要几十秒，所以请求要带 `keep_alive`，让模型常驻。
- 样例：输入 "I want to learn"，候选为 ` English / how / to / the / more`。

## 工程约定

- 根目录可见文件夹只有 `a-*`、`b-*`、`z-*`；新增目录要登记进 manifest 的活动目录。业务代码放到将来新建的 `b-Code-*` 组件目录，`b-Code/` 只放项目维护工具。
